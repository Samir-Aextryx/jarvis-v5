# Jarvis v5 repository and Jev update — 23 September 2026

The root Python source was grouped into the `jarvis` package (`core`, `voice`, `integrations`, `automation`, `routers`). Documentation is under `docs`, maintenance scripts under `scripts`. The source root has no Python modules. macOS Swift/Bash helpers and AppleScript integrations are removed from this Windows-only application. The former `server.py` measured about 3,500 lines and now measures 1,928 lines. Voice, personal, integration, automation and system endpoints have separate FastAPI routers. The long assistant prompt and background task manager have separate modules. The routers still use the server module as a runtime bridge, so dependency extraction is incomplete.

`pytest` and `pytest-asyncio` are installed and listed in requirements. The outdated Windows-calendar and email assumptions were replaced with tests of current behavior, including verified drafts and explicit send requests. Final regression run: **270 passed, 1 skipped, 61 subtests passed**. The skipped case is an external browser search. TypeScript, Vite, seven Node tests and an isolated packaged-backend smoke check passed. The desktop app opened, the Jev input and `[JEV_KEY_MISSING]` were visible, and installed backend health/settings/memory/calendar requests returned HTTP 200. No real test email was sent.

The Windows Credential Manager now holds the local auth token, including a verified migration from the existing `.env`. The Electron shell receives it through an internal child process and preload bridge. Voice and transcription WebSockets require it in the protocol handshake; URLs no longer carry it. Failure to write the vault retains the old plaintext value rather than destroying access. The installed `.env` has no auth-token assignment. Other old logs and browsers may still contain earlier URL requests; this update does not erase browser history.

A synchronized shared context cache, serialized per-socket output and a lock on concurrent background task starts guard the identified races. Broad exception catches in the split server and route modules now log the failing operation, exception type and source location without logging user content. Many broad catches remain and should be narrowed only after their individual recovery behavior is characterized.

Vite now places Three.js in a separate 492 kB chunk; the main JavaScript chunk is roughly 64 kB. This improves initial transfer when Three.js is cached or not immediately needed; it does not halve the total JavaScript delivered to an orb view. Frontend settings share an API helper.

The previous 2.7 GB `backup-updates` folder was archived into a checksum-verified 436 MB archive at `%USERPROFILE%\Documents\Jarvis v4\jarvis-backend-backups-20260922.zip`. Original backup and obsolete build folders were moved reversibly into `%USERPROFILE%\Documents\Jarvis v4\archive-originals-20260922`, outside the Git repository. They still consume disk space. `scripts/restore-backups.py` restores the archived backups only into a new empty destination. The user's `jarvis v5 backup` remains untouched.

Atlassian `twg login --force` was launched twice. Browser authorization was not completed before its two-minute timeout, so Jira/Confluence still lack that login. The user must finish `twg login --force` in an interactive terminal. No authentication barrier was bypassed.

Remaining work: remove the server runtime bridge in stages, narrow error boundaries, migrate every historical script and benchmark to the new paths, and review platform conditionals. Source tests and the installed core app flows are verified, but hardware speech latency, every external account and all desktop actions were not revalidated end to end. Future updates should use `scripts/check-and-build.ps1` before packaging.
